Scion Project

Apple's open-source kernel,
on Android phones.

Scion runs XNU, the kernel under iOS, directly on the Galaxy S9: no emulator and no Android underneath, with drivers written for the phone's own hardware. iOS 16.5 and iOS 27 both start on it, from one kernel tree built on two of Apple's XNU releases. A contributor has run it on the Galaxy S9+. On the Pixel 10, iOS 16.5 runs in a virtual machine through the Scion app, and a bare-metal iOS 27 port has so far run only in QEMU.

It is an experiment, not a finished system. You build every image yourself, on your own computer, from your own copy of iOS. These repositories contain no Apple software.

The aim

One kernel tree for every phone Scion runs on, running on the phones themselves, with Android kept beside it.

One tree

Scion's kernel is one tree built on two of Apple's XNU releases: xnu-8796 for iOS 16.5 and xnu-12377 for iOS 27. The drivers, the SoC layers and the phones' descriptions are shared; what differs is Apple's source and the changes made on it. The Galaxy S9 and the Pixel 10 are two machine configurations of the same iOS 27 tree, and the S9's audio and Bluetooth drivers build for both releases.

Sources: scion-kernel docs/two-bases.md, docs/ios27/PIXEL10.md; xnu pull request 24; scion-kernel pull request 280.

On the phone

On the S9 the kernel runs on the phone's own eight cores. On the Pixel 10 the virtual machine is the route that works today; the bare-metal port, where Google's boot loader starts Scion's loader and the loader starts XNU, is written and runs in QEMU, and has not been run on a phone.

Sources: scion-starlte device.conf; scion-frankel README.md, device.conf.

Beside Android

Not yet on the S9. Today installing iOS 16.5 replaces Android's system partition and installing iOS 27 erases Android's data; Android comes back from your backups. Choosing iOS or Android at power-on, with Android's data kept, is designed for the S9 and has not been run on a phone.

Sources: scion-kernel docs/dual-boot-s9.md, docs/ios27/INSTALL-S9.md.

How to try it

Why there is no download button. An image contains iOS's own files, taken from a restore image. We cannot distribute those and neither can you, so you build it yourself, from an IPSW you download from Apple. It is yours: do not share it.

iOS 16.5 on a Galaxy S9: the installer

You need an Exynos Galaxy S9 (G960F, FD models too) with an unlocked boot loader and TWRP, a Mac or Linux machine with about 20 GB free, and the iOS 16.5 IPSW for iPhone10,3/10,6 (20F66), downloaded yourself.

  1. Back up. In TWRP, back up Boot, System and EFS, and copy the backup off the phone. EFS holds your IMEI.
  2. Build (about 20 minutes): 
    git clone https://github.com/Scion-Project/scion-installer
cd scion-installer
./build-installer.sh --ipsw /path/to/iPhone10,3,iPhone10,6_16.5_20F66_Restore.ipsw
    It checks your IPSW, lists any missing tools with the command to install them, downloads nothing from Apple, and writes the zip and its SHA-256 to ./out. --device star2lte, crownlte or all adds the S9+ and Note9 test images.
  3. Flash. Copy the zip to a microSD card or to /sdcard with adb push (adb sideload cannot take a zip over 2 GB), then install it in TWRP. It checks the model, writes SYSTEM and BOOT, verifies both, and refuses to touch EFS, the modem or recovery.
  4. Reboot to System.

Leaving: hold five fingers on the screen for 1.5 seconds to restart into TWRP with the log, or force a restart with Vol Down + Power. Restore your Boot and System backups to get Android back.

Installer: details and troubleshooting

iOS 27 on a Galaxy S9: the documented build

No installer: you build the kernel, the boot image and the root on an Apple silicon Mac with about 110 GB free, Xcode 16.4, the Kernel Debug Kit 26.5 and the iPhone 11 restore image 24A446, then write them from TWRP over USB.

  • It erases Android's data. Android's system partition, TWRP and the boot loader are not touched.
  • Starting. Samsung's S-Boot starts Scion's boot loader from BOOT, which shows a menu with a countdown before it starts iOS 27. Three failed starts fall back to Scion recovery. Holding Bixby while starting iOS from the menu gives a verbose boot.
  • The kernel, the loader, the boot image and the instruction rewrite have been run from a clean clone. The graphics libraries and the last steps of the root have not; expect to find a mistake there, and please report it.
  • The root steps that let iOS use Wi-Fi, the sensors, audio, Bluetooth and the modem are separate scripts the one-command root build does not run yet.
  • It can hang. The kernel returns to TWRP by itself 24 hours after every boot.

Being worked on now

  • Power

    The phone never sleeps. An idle core waits powered, no power domain is switched off when idle, and the buses run at the rates the boot loader left. It is the largest gap in what Scion drives of the S9.

    scion-starlte docs/hardware-map.md, "Power"

  • Frame rate under Metal

    With the Metal compositor, swiping the home screen keeps 43 to 67 % of frames on time and scrolling inside an app about 95 %. Landscape rotation with the Metal compositor was fixed on 18 November.

    scion-kernel docs/ios27/INSTALL-S9.md, "Known problems", "What works"

  • The iOS side of 17 November

    The S9's hardware is on by default in the iOS 27 kernel. What iOS needs on top (the sensors' library, Wi-Fi's firmware and service, the audio and Bluetooth step, the cellular daemon) is still separate root steps, and the image with everything on has not yet been run on a phone.

    scion-kernel docs/ios27/INSTALL-S9.md, "The S9's hardware is on by default"

Known problems

iOS 27

  • It can hang hard, console included, some minutes into a session; the cause is not found. Volume Down + Power for about ten seconds gets out of it.
  • It is slow in places, and the first picture takes 18 to 40 seconds.
  • The lock screen's clock is not drawn, and the wallpaper picker does not work.
  • A few system services still crash at start. Widget extension crashes were fixed on 18 November.
  • Only build 24A446 works; another restore image is refused.
  • No passcode in the documented build.

iOS 16.5

  • One tester has reported the phone restarting by itself. The cause is not known yet.
  • No rear cameras, and no headphones.
  • Settings are lost at each restart unless USERDATA is formatted for Scion, which erases Android's data.
  • The passcode protects keychain items only. Your files are not encrypted, and a short code can be guessed offline by anyone who reads the flash.

Both

  • No calls and no SMS. The phone never sleeps.
  • No App Store, Apple ID, iCloud or iMessage, and that is not a goal. Nothing here makes a phone pass as an iPhone to Apple.
  • Snapdragon models are not supported.

Report a problem, or that it worked

Save the logs in TWRP right after the problem, before anything else, then open an issue with your phone's model and the log, or a tester report if it worked. How to save the logs. Never attach an installer, a system image, a root image or an IPSW: they contain Apple's files.

If you have an S9+ or a Note9, the first-run log is the most useful thing you can send. Code, documentation and driver reviews are welcome on GitHub.

Questions

Is this an emulator?

Not on the Galaxy phones: the kernel runs directly on the phone's cores, with drivers for its own hardware. On the Pixel 10 the Scion app uses an emulator or Android's hypervisor; the bare-metal Pixel 10 port has run only in QEMU so far.

Can I use the App Store, iCloud or iMessage?

No, and that is not a goal. Nothing here makes a phone pass as an iPhone to Apple's servers.

Why can't I just download an image?

An image contains iOS's own files, which only Apple may distribute. You build yours from an IPSW you get yourself, and it stays yours.

Can I go back to Android?

Yes. On iOS 16.5, restore the Boot and System backups you took in TWRP; the installer never touches EFS, the modem or recovery. On iOS 27, flash Android's boot image back and format data in TWRP: Android starts as after a factory reset, because the install erased its data.

Is the passcode real security?

Not yet. On iOS 16.5 keychain items are encrypted under a key derived from your passcode, and forgetting it loses them, but files are not encrypted, there is no hardware-bound key, so a short code can be guessed offline from a flash dump, and an unlocked boot loader lets anyone with the phone flash a modified kernel. The iOS 27 build has no passcode at all. Do not rely on either to protect secrets.

Does it work on the Snapdragon S9?

No. Only the Exynos 9810 models.
